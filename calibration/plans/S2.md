# S2: model × effort screen with the E7 instructions (sequential, one run per configuration)

**Status:** written while the first run was in progress (08:12 UTC). The configuration was fixed before it started; the judging and reading below are fixed now, before any result is seen.

**The decision it informs:** whether a higher effort level, or Opus, is worth its cost for planning, beyond Sonnet at high with the E7 instructions. That configuration passes the central gate in 8 of 8 plans (E7, batch J8). It is the hypothesis that proof-mining has a steep effort–quality curve.

**Design: one fresh argument run per configuration, run one at a time**
- **The task:** the argument task of E6's extraction F1 (background accepted), rendered by the E7 binary (`141026-exp-key-step-identity`, 91c4fed). The task file is byte-identical to E7's F1W apart from the project path (checked by diff).
- **The subagent:** `general-purpose`, with the prompt `exegenius next` prints, word for word.
- **The reference:** E7's F1W (Sonnet, high), not rerun.

**Rules:**
- Serial, never parallel, near a usage limit.
- Each run's outputs, transcript, model, effort, tokens and seconds are recorded before the next starts.
- A run killed by the usage limit is an operational failure, not a result. Its scratch files are moved aside, and it is rerun after the reset.

**Judging** (after the runs, when quota allows):
- **Plans:** the four new plans and the reference F1W, blind, in one batch.
- **Judges:** **three independent judges per plan**, each step decided by majority (E7's finding: single-judge gate verdicts are noisy).
- **Instructions:** J3's, unchanged.

**What is read, one run per configuration being a screen:**
- **Reported per plan:**
  - central steps C1–C9 by majority;
  - the gate;
  - core derived and faithful counts;
  - major errors;
  - argument seconds, tokens (cache read, output) and, where available, cost.
- **A configuration is worth a repeat** if it differs from the reference by more than judge noise on central steps or faithful derivations, in either direction, or costs much less for the same result.
- **What a single run cannot do:** establish a ranking or an equivalence.
- **Bad results:** no configuration is dropped on one bad run alone unless it also costs more. Poor results are kept and reported.
