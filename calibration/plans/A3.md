# A3 (concluded 2026-10-17, row 1): does one paragraph on what counts as an error cut the source-aware audit's false alarms?

**Status:** preregistered on 2026-10-17 at 17:55 UTC, before any A3 model call. This is the one narrowly scoped refinement the author allowed on 2026-10-17 ("if one narrowly scoped instruction refinement is warranted, test it"). There is one arm and one run. Whatever it shows, the audit recommendation is then made from the rows below; no further audit experiment follows.

## Why this refinement

- **A2 (row 1)** showed that the source-aware structured audit (SI) catches what the current audit cannot: 13/13 source-only errors against 0/13, and 26/28 page errors against 14/28.
- **The independent review** (`plans/A2.md`, R3) then found only 3 of SI's 9 clean-page alarms genuine, so F_A was 1.00 per clean page against ≤ 0.5.
- **What the rejected alarms have in common:** correct statements flagged because they were simplified or abbreviated, used a word in the paper's own sense, left a technical precondition to the paper, or matched the paper's own summary of the step.
- **The test:** one paragraph naming that class.

## The arm (`tools/a3setup.py`)

**R:** A2's SI task, with REFINE inserted after the SOURCE paragraph. Nothing else changes. The script checks that each task equals the rendered task plus exactly FIDELITY, SOURCE and REFINE, with SI's widened restriction. REFINE reads:

> What counts as an error: report a claim as wrong only if, as this page states it, it is false; inconsistent with the page; stated more strongly or more widely than what supports it; missing a hypothesis without which it is false; given a wrong value, sign, exponent, constant, quantifier or credit; or presented as following from something it does not follow from. Do not report a correct statement as wrong because it is informal, abbreviated or simplified, uses a word in the paper's own sense, or leaves a technical precondition to another page or to the paper. If the paper's own summary of the same step states it the same way, it is not an error.

**The rest is as in A2:**
- Sonnet `high`, as `general-purpose` subagents, prompts word for word.
- A2's key (30 variants, 48 errors, 18 shams) and the same binary (sha256 c37a2b3d…).
- 30 copies in the scratchpad's `a3/runs/A3R1/` (made at preregistration, with no problems).
- Isolation by `a1collect.py --allow sources/paper.tex`. A contaminated task is rerun once.

## Measures and comparators

**R's measures:**
- R_src (13), R_page (28), R_quote (7) and F_sham (18), as in A2.
- Hand labels decide "named": A2's labelling rule, applied by this session, masked; `ASSERTS` is reported beside them.
- **F_A** (per clean page, 6 pages) is decided by **an independent blind reviewer, not by this session.** A fresh Opus subagent judges R's clean-page asserting gaps outside native defects, by A2's review protocol (`tools/a2review.py`'s rule and task text, masked notes, the same four decoys, no arm information).

**Comparators** (A2, already measured; not rerun):
- B: R_src 0/13, R_page 14/28.
- SI: R_src 13/13, R_page 26/28, independent-review F_A 1.00.

## Weaknesses (stated)

- **One run, one paper, six clean pages:** F_A rests on few alarms.
- **The labeller knows the arm:** only one arm runs, so hand labels for "named" are not blind to arm. F_A, the fragile measure, is the independent reviewer's.
- **The comparators** are from A2's run, not run alongside R.
- **REFINE was written after seeing A2's rejected alarms.** It targets them by design, so a pass shows it fixes the observed failure, not that it generalises.

**How fragile the pass is, stated plainly:**
- **F_A is exactly at its bound.** One more false alarm on six clean pages would fail it.
- The three alarms the reviewer rejects are 44, 79 and 104, and it marks all three borderline. In each, the page omits a hypothesis or condenses a step, but the quoted statement is true: the reviewer finds the paper establishes it by another route or in shorthand.
- With those borderline verdicts flipped, F_A would fall to 0. No flip in the other direction is available.
- REFINE was written after seeing A2's rejected alarms (stated at preregistration). This pass shows it fixes the observed failure, not that it generalises to other pages or papers.

**What the refinement did** (R against SI, both reviewed independently; exploratory):
