# Evaluation Registry: record format

The registry holds one record per experiment:
- **records**, built by `../tools/registry.py build` into `experiments/<ID>.json`;
- **specs**, hand-written into `specs/<ID>.json`;
- **judge batches**, defined in `judging.json`;
- **an index**, `INDEX.md`, generated by `../tools/registry.py index`.

## Rebuilding

From the repository root, with lmmx/openai-nlogn-wiki cloned and its experiment branches fetched:

```
python3 -I calibration/tools/registry.py build calibration/registry/specs/*.json \
    --wiki PATH/TO/openai-nlogn-wiki --out calibration/registry/experiments
python3 -I calibration/tools/registry.py index calibration/registry/experiments/*.json \
    > calibration/registry/INDEX.md
```

The build reads git objects at each spec's evidence commit, so it is reproducible from the refs alone.

## Bases

Every extracted value is an object `{"value": …, "basis": …}`:

| Basis | Meaning |
|---|---|
| `measured` | extracted by the builder from run logs, transcripts or verdicts |
| `estimated` | computed with a stated approximation (output tokens: content characters ÷ 4) |
| `reported` | taken from a source the builder cannot read (a session's reported cost, a journal's figure), with `source` naming it |
| `unavailable` | not recorded anywhere; `note` says why. Never filled in by inference. |

## Spec (hand-written)

| Field | Meaning |
|---|---|
| `id`, `title`, `kind` | `kind` is `controlled` (arms differ in a stated dimension) or `observational` |
| `question` | what the experiment asks |
| `document` | `name`, `title`, `class` (the document class a result is scoped to) |
| `task` | the task or stage studied |
| `binary` | lmmx/exegenius commit that wrote the task files |
| `evidence` | where the runs are: `repo`, `branch`, `commit` (or `path` for evidence kept in this repository) |
| `evidence` (optional) | `transcripts`: the transcripts' path at the commit (default `results/transcripts`); `description_prefix`: prepended to the run named in a subagent's description, for runs renamed in the evidence; `planning_kinds`: the task kinds a run's planning consists of (default extract, background, argument, extend); `log_since`: an ISO time before which a run's log events are ignored, for runs copied from an earlier run's project |
| `protocol`, `journal` | the runner protocol and the journal entry |
| `arms` | `{ARM: {"intended": {...}, "runs": [...]}}`. `intended` gives `agent`, `model` or `model_id`, `effort` (null when not passed), `effort_passed`, `checks`, and optionally `binary` when an arm's task files were written by another binary than the spec's |
| `excluded` | `{RUN: reason}`: runs kept in the record but left out of summaries |
| `runs_extra` | per-run facts the builder cannot extract (for example `observed_config` with its basis and source) |
| `reported` | facts with basis `reported`, such as `session_cost_usd` |
| `limitations` | stated limits |

## Record (built)

A record holds every spec field, and adds:

| Field | Meaning |
|---|---|
| `built` | the builder and the wiki commit read |
| `orchestrator_observed` | the models and effort of the runner session's own turns, from its main transcript |
| `runs[]` | one per run. See below. |
| `arm_summary` | per arm: run count; per judge batch, the medians and ranges of each quality count over first judgements; per planning task, the medians and ranges of resources; planning seconds |

**Per run:**
- **`planning_tasks`:** each planning task's issue time and submits (attempt, time, outcome, check, coverage figures), from `log.jsonl`.
- **`planning_seconds`:** from the first planning task issued to the last accepted.
- **Submits:** `rejected_submits`, `coverage_rejections`, and `other_tasks_issued` (the write tasks handed out when planning ended).
- **`subagents[]`:** per subagent, `agent_type`, `models` (each model with its number of assistant messages), `effort` (each value with its number of records), `model_calls`, `input_tokens`, `cache_read_tokens`, `cache_write_tokens` (measured), `output_tokens` (estimated) and `seconds`.
- **`observed_config`:** the agent types, models and efforts the transcripts record.
- **`matches_arm`:** whether they equal the arm's intended configuration. Only the fields the arm specifies are checked, and the value is null when there are no transcripts.
- **`quality[]`:** one entry per judgement of the run's plan:
  - `batch`, `judge` (`a` first, `b` second), `plan` (its blind id);
  - the content judge's counts: `core_stated`, `core_fully`, `core_derived`, `core_faithful`, `supporting_stated`, `wrong`, `major_errors`, `minor_errors`;
  - where the batch used the central-derivation rubric, `central_count` and `central_gate`.

Run names are global across experiments (A1–A6, B1–B6, C1–C5, D1–D5, P1–P5, G1–G5, M1–M5, sonnet1–2), so a judge batch's key maps blind plan ids to run names. A run judged in several batches has an entry from each.

## Judge batch (`judging.json`)

| Field | Meaning |
|---|---|
| `id` | J1, J2, … |
| `dir`, `key`, `verdicts` | where the batch's key and verdicts are, relative to the repository root |
| `reference` | the reference set the verdicts refer to |
| `judge` | the judges' agent type, model and effort |
| `seed` | the blinding shuffle's seed |
| `rubrics` | rubrics applied, such as `calibration/rubrics/nlogn-central-saving.md` |
| `journal` | the entry that reports the batch |

## What the registry does not hold yet

- **The full runs' audit-round figures** (journal 2026-10-13-convergence-before-after). Those runs have no transcripts and a different shape (rounds, not arms). Their recorded `exegenius status` output is kept in that entry's directory, to be added as observational records once a run records its configuration.
- **Writers, auditors and support checks:** no controlled experiment on them yet.
- **Subscription quota:** unavailable by design (see `../PROTOCOL.md` §7).
