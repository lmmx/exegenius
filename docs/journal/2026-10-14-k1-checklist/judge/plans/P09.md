# Plan P09

The plan of the argument for the main theorem, as a tree of steps.

- **S0** (show, page `main-theorem`): There is one deterministic fixed-alphabet, fixed-tape Turing machine that multiplies $n$-bit integers exactly in $O(n(\lg n)^{1-\kappa})$ time, with $\kappa=2^{-182}$, which disproves the $n\log n$ optimality conjecture in this model.
  - method: Reduce the refutation to the upper bound, then build the algorithm bottom-up: the two power-saving tape procedures (address-chunk interchange and simultaneous butterfly layers), the exact ring convolution that uses them, the multiplication algorithm with its exactness proof, and the parameter balance.
  - motivation (explicit): A transform-based multiplier pays $\Theta(n)$ per level over $\Theta(\log n)$ levels, which is already $n\log n$, so going below it needs savings in both data movement and arithmetic; the proof therefore builds the two procedures that supply them first and assembles the multiplication on top.
  - relies on: nlogn-conjecture, nlogn-multiplier, fixed-tape-model, chunk-interchange, simultaneous-layer, ring-convolution, mult-algorithm, parameter-balance, tape-machines, big-o, asymptotic-notation-beyond-big-o, logarithms-and-exponentials, determinism-and-exact-versus-approximate-computation
  - **S0.1** (infer): Refuting the conjecture needs only one machine $A$ with $\liminf_{n\to\infty}T_A(n)/(n\lg n)=0$, the negation of an eventual bound $T_A(n)\ge c_An\lg n$, and a power saving gives this limit through all input lengths.
    - relies on: nlogn-conjecture, asymptotic-notation-beyond-big-o, big-o
    - quotes line 384: "Its negation requires one machine satisfying $\liminf_{n\to\infty}T_A(n)/(n\lg n)=0$. The power saving proved here gives a limit of zero through all input lengths, which is a stronger conclusion."
  - **S0.2** (show, page `chunk-interchange`): Two disjoint address chunks of $u$ bits, anywhere in an array whose addresses form a complete Cartesian product, can be interchanged in $O(Vu^\tau)$ tape steps for a fixed $\tau<1$, although the intermediate steps form XOR combinations of the data.
    - method: Use linear-time stream tools together with the key step, a recursive interchange of chunks of $m^k$ digits driven by a fixed rank-saving bit network, and then remove its restrictions on width and row count.
    - motivation (explicit): An edge matrix of rank $a$ needs $a$ smaller interchanges and the ranks sum to less than the number of wires times $m$, so the resulting recurrence saves a power of the chunk width.
    - relies on: power-interchange, stream-ops, controlled-shifts, array-order, fixed-tape-model, binary-field-f2-and-xor
    - **S0.2.1** (infer, page `stream-ops`): Splitting on a radix-$q$ digit, permuting digit values, moving a digit, applying a pointwise map to aligned streams, merging, and splitting whole rows cyclically into a fixed number of equal streams each take $O(V)$ steps on a fixed number of tapes.
      - relies on: array-order, fixed-tape-model, positional-number-representation-and-carries
      - quotes line 493: "Fix a radix $q\ge2$. Each of the following operations on an array of volume $V$ takes $O(V)$ steps on a fixed number of one-dimensional tapes: \begin{enumerate} \item any fixed permutation of the pair of digit values at two specified radix-$q$ positions, whether or not the positions are adjacent; \item moving one specified radix-$q$ digit to another position, preserving the order of the intervening positions; \item splitting on a specified radix-$q$ digit, applying a fixed pointwise map to aligned streams, and merging them back; \item for positive integers $P,R,B$, within each prefix of an array on $[P]\times[R]\times[B]$, splitting whole rows cyclically into a fixed number $W$ of streams, and, when $W$ divides $R$, merging those streams in any fixed order of the row classes."
