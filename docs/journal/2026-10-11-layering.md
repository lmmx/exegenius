# 2026-10-11: Layering, fragmentation and collapse

This entry implements the sixth research entry, 2026-10-11-fragmentation-and-collapse. That entry decided where the outputs of the earlier entries appear, so that page bodies stay self-contained while the cross-page structure becomes visible, and how to tell which way a wiki is failing. The placement was built with entries 1 to 5; this entry records it against the research entry's five layers, and adds the measures.

## The layers, as built

| Layer | Research entry | Built |
|---|---|---|
| 1. In the sentence | one signalled sentence per prerequisite | each prerequisite page needs a relation whose sentence is on the page and links or names it (2026-10-11-relations) |
| 2. Page chrome | "Before this page" with predicates; "Where this fits"; inherited symbols | "Before this page" as predicate triples, open; "Where this fits" breadcrumb, open; "Symbols from earlier pages", folded |
| 3. Tooltips | symbol meanings; prerequisite quotes on hover | relation sentences as link tooltips in "Before this page" and "Used by"; glosses on other links; no symbol tooltips |
| 4. Separate pages | dependency view (exists), mechanism view, significance view | the argument's top two levels on the front page; the notation page derived from bindings; the significance view ("Key steps") in the report, not on the site |
| 5. Author-side report | the gap view | `exegenius/report.md`, out of `docs/`: predicate counts, sentences that carried key points, key ideas, joining sentences, ablations, and the measures below |

This settles the research entry's open questions 1 and 2 as built: the breadcrumb is the zoom-out and stays open; the inherited symbols fold; "Before this page" stays open, since it is now a single sentence; and the significance view stays in the report until ablations confirm sentences.

## The measures

### Signs of fragmentation

The report's "Navigation" table gives, per round (exegenius-core/src/report.rs:74):
- **pages opened per run**, the front page aside, counting each page once;
- **the share of opened pages a reader left without citing**, a reader who opened a page and found nothing to use there;
- **runs on goals that need several pages that cited only one**, out of the answered runs on such goals.

Stuck points of level `chain` are counted in the level table from 2026-10-11-goal-kinds.

### Signs of collapse

The simulation records each page body's word count when each round's readers set out. The report's "Page length by round" table gives the total words and pages per round, and the five pages that grew most from the first recorded round to the last. This answers the research entry's open question 3: lengths are recorded, so growth shows before it is felt.

The research entry's redundancy measure, unique statements over total across the pages a goal needs (Altemeyer et al.), needs an agent to judge what counts as the same statement, and is not built.

### A length budget on rewrites

Rewrite tasks now tell the writer the previous version's word count and a budget of a quarter more, at least 50 words more for short pages. The task asks for fixes by restructuring rather than appending, unless a problem cannot be fixed without more. Submit warns when a rewrite goes over the budget, but does not reject it (exegenius-core/src/write.rs:427). This answers open question 4 between the two options: a rejection could block a rewrite that an audit note genuinely asked to explain more, while a budget with no signal would be ignored.

### The expertise-reversal test

With more than one reader profile (`[[readers]]`), the report's "By reader profile" table gives each profile's runs, answers, key point coverage and pages opened per run. If the wiki helps the novice and slows the expert, the second profile's row shows it.

## How it was tested

The end-to-end simulation test checks the navigation and page-length tables on its scripted runs. A unit test builds a two-profile simulation and checks the profile and navigation rows. None of these measures has been run on the demo with agents.

## Current State
- `Simulation.words` records each page body's word count at the start of each round, saved when the round's read tasks are issued (exegenius-core/src/simulate.rs, exegenius-core/src/task.rs)
